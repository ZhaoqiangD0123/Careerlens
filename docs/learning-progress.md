## 本次决策与复盘：一键报告导出

- 目标：用户只提供原始岗位 JSON，直接得到可阅读的岗位观察报告。
- 输入：最外层为数组的原始 JSON，允许合法、无效、重复岗位混合存在。
- 流程：`read_json_file` → `filter_job_records` → `deduplicate_job_records` → `build_job_statistics` → 写入 Markdown。
- 选择原因：复用已有模块，使单独命令与一键命令遵循同一套校验、去重和统计规则。
- 输出：`reports/job-market-summary.md`；包含处理数量、城市分布、常见技能和最终岗位列表。
- 边界：输出不能覆盖输入；无效岗位和重复岗位不参与统计；本次不把中间 JSON 自动写回磁盘。
- 验证：21 项自动化测试通过；对 23 条演示数据实际运行，得到 11 条最终岗位。
- 已知限制：技能统计仍依赖预定义关键词；演示来源链接不是经过真实性验证的招聘链接。

本次关键提示词（节选）：

> 将清洗、去重、统计之类的功能合并起来；只要输入原始数据，就自动导出报告。

## V1a-01：首条 HTTP 接口（实现完成，用户验收待完成）

- 学习目的：理解客户端请求如何进入 Python 应用，再通过 HTTP 返回 JSON。
- 建议契约：`GET /jobs`，读取服务端 `data/deduplicated_jobs.json`，返回 `total` 和 `items`。
- 状态约定：正常与正常空数据均为 200；数据源缺失或损坏为 500，不能当作空列表。
- 技术职责：Uvicorn 监听请求，FastAPI 组织路由与响应，现有模块负责读取和岗位校验。
- 用户授权：按既定契约实现，并告知本机已安装 Apifox，后续用它手工调试。
- 模块调整：新增 api.py、job_files.py、test_api.py；explore_jobs.py 改为导入公共读取函数；更新依赖、锁文件与 README。
- 验证：真实 Uvicorn 服务的 GET /jobs 返回 200、total 为 11、items 为 11 条；/docs 和 /openapi.json 可访问。接口测试涵盖正常、多条、空数据、失败、只读、每次重新读取、404/405 与文档。
- 最终回归：33 项测试全部通过；Git diff 格式检查通过。验证服务已停止，用户实践时需自行启动。未提交或推送本次改动。
- 限制：每次请求完整读取文件，无分页、缓存或认证；第一版只在 127.0.0.1 本机调试。数据文件需要预先清洗去重，API 不自动重新去重。
- 下一步：用户启动服务，用 Apifox 请求并核对响应，审查 diff、解释请求流与错误路径，之后决定 Git 提交。
