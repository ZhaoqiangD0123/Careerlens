# CareerLens 学习进度与任务日志

更新日期：2026-09-29

## 当前定位

CareerLens 是 Python 后端与 AI 应用工程的长期作品集项目。当前处于 V0 命令行版本：用 JSON 岗位数据练习校验、清洗、文件处理、测试、统计和报告导出。

## 已完成的功能

1. 定义岗位字段并校验单条 JSON 数据。
2. 批量清洗和过滤岗位，保留无效数据的错误原因。
3. 按 `source_url` 去重，保留第一次出现的岗位。
4. 展示、搜索、筛选岗位，统计城市、岗位和技能关键词。
5. 从原始 `data/jobs.json` 一键生成 Markdown 报告：自动过滤、清洗、去重、统计和导出。

演示数据处理结果：原始 23 条、无效 11 条、重复 1 条、最终保留 11 条。自动化测试共 21 项。用户曾在新目录从 GitHub 克隆项目，运行 `uv sync --group dev` 并通过当时的 19 项测试；本次新增报告功能后，还需在新克隆目录再次复现。

## 本次决策与复盘：一键报告导出

- 目标：用户只提供原始岗位 JSON，直接得到可阅读的岗位观察报告。
- 输入：最外层为数组的原始 JSON，允许合法、无效、重复岗位混合存在。
- 流程：`read_json_file` → `filter_job_records` → `deduplicate_job_records` → `build_job_statistics` → 写入 Markdown。
- 选择原因：复用已有模块，使单独命令与一键命令遵循同一套校验、去重和统计规则。
- 输出：`reports/job-market-summary.md`；包含处理数量、城市分布、常见技能和最终岗位列表。
- 边界：输出不能覆盖输入；无效岗位和重复岗位不参与统计；本次不把中间 JSON 自动写回磁盘。
- 验证：21 项自动化测试通过；对 23 条演示数据实际运行，得到 11 条最终岗位。
- 已知限制：技能统计仍依赖预定义关键词；演示来源链接不是经过真实性验证的招聘链接。

本次关键提示词（节选）：

> 将清洗、去重、统计之类的功能合并起来；只要输入原始数据，就自动导出报告。

## 学习验收状态

代码已交付、测试已通过。是否达到“本人掌握”仍需用户审查 Git diff、亲自调整一个小点，并用自己的话解释以下问题：

1. 原始数据如何依次变成最终报告？
2. 为什么去重放在清洗之后？
3. 无效岗位和重复岗位为什么不计入城市、技能统计？
4. JSON 格式错误、全部岗位无效、输出路径与输入相同时会发生什么？
