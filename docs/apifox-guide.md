# CareerLens：导入 Apifox 并验证响应

## 导入文件

文件：`careerlens.postman_collection.json`，格式为 Postman Collection v2.1，不要求安装 Postman。Apifox 支持该格式与 pm 脚本。

1. 保持 CareerLens 服务运行。
2. 在现有 Apifox 项目进入“项目设置 → 导入数据”。
3. 选择 Postman，上传本目录的集合 JSON 文件。
4. 在预览中核对四个请求和后置脚本，选择导入到新目录；保留已有接口，不开启删除未匹配接口的同步选项。
5. 按官方导入说明，在环境页勾选与集合同名的环境；确认 baseUrl 为 `http://127.0.0.1:8000`，然后导入。
6. 调试时选择该本机环境，确认实际发送地址是 127.0.0.1，不是 Mock 或云端地址。

如果变量没有自动转换，可在环境管理中把前置 URL 设置为 `http://127.0.0.1:8000`。仅用于本机学习，不填密码或令牌。

参考：[Apifox 官方 Postman 导入说明](https://docs.apifox.com/doc-5174528)。

## 四个请求

| 请求 | 预期 | 检查内容 |
| --- | --- | --- |
| GET / | 200 | 当前用户新增响应 `{"Hello":"world!"}` |
| GET /jobs | 200 | JSON、字段、非负整数 total、items 数量一致 |
| GET /__careerlens_test_not_found__ | 404 | 错误响应包含 detail |
| POST /jobs | 405 | 方法不允许，错误响应包含 detail |

发送后查看后置操作的断言执行结果。404、405 请求如果符合预期，也应显示测试通过。导入的负向请求只是客户端测试，不需要为它们添加 Python 路由。

集合内没有固定断言 total 等于 11；以后增加合法岗位，结构与数量仍应一致。正常空数组也可通过这份契约测试。

若导入后没有后置脚本，在“获取岗位列表”请求的“后置操作”中添加自定义脚本，粘贴同目录 `apifox-jobs-post-response.js` 的内容。脚本用 JavaScript 自动核对响应，无需记忆语法。参考：[官方断言说明](https://docs.apifox.com/assertions)、[pm 脚本 API](https://docs.apifox.com/pm-%E8%84%9A%E6%9C%AC-api-5580997m0)。

## 你需要理解的流程

请求配置 → Apifox 向真实服务发送 HTTP 请求 → 收到响应 → 后置脚本断言 → 查看是否符合契约。

接口文档描述约定；请求实际调用服务；断言自动比较实际结果与约定。它们不是同一件事。Apifox 通过真实端口调试，pytest 的 TestClient 在进程内测试，两者互补。

## 范围与边界

- 本次没有创建 Apifox 的“自动化测试场景”；导入后可以先逐条运行，再将请求加入场景。
- 500、损坏数据和正常空文件由现有 pytest 临时文件测试覆盖，不要为本机调试删除或破坏正式数据。
- 如果以后调整根路径响应，请同步调整 Hello World 请求的断言。
- 不设任意响应时间上限；性能测量应在后续确定数据规模与环境后进行。
- 导入文件与脚本可进行本地格式、语法及 HTTP 验证；最终导入映射和脚本执行效果仍需在你的 Apifox 中确认。

遇到导入、环境或测试失败，可把截图与实际请求地址发给 Agent，不需要从头重建服务。
